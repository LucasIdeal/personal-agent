## 6. 记忆写入、抽取和检索

**意图：** 别逢聊必记；抽取要干净；检索留在本机。

> 目前记忆有点乱 用户随口说一句也会被记进去  
> 我希望只有明确说「记住 / 记下 / 记一下」才写入 侧栏确认卡片也可以写  
> 晚上再扫一遍昨天的对话 带时间的别进记忆 进待办  
> 问「你记着什么」只检索 不要再写一条进去

> 抽取先用规则分句 抽不出再调 llm 别一上来就调模型  
> 口味习惯走 preference 身份信息走 fact  
> llm 只允许吐 json 解析失败或超时就退回规则结果 空着也行 千万别把半截回复写进 sqlite

> 扫描抽出来好多寒暄和 markdown 「老师您好」这种不要 助理自己说的也不要  
> 只看用户原话 插件打进去的用户画像那些消息也跳过  
> 一天最多扫成功一次 别重复扫把库写脏

> 同样的话记了两遍 按内容做个指纹去重 一样的就更新 别再插一行

> 检索别走云端 embedding 密钥和记忆都留本机  
> 关键词加一个本地向量 两个通道一个命中就算 不要做成必须同时命中  
> 中文按 2/3-gram 切开 英文按词 中英混在一起也能搜到  
> info_search 把待办 订阅 笔记一起搜

> 对话里别每轮把全库记忆塞进 prompt 太多了  
> 常驻只要一份用户画像 大概几十条 active 就够  
> 真要查某条再用 memory_manage search  
> 没记忆就别注入 省点 token

> 侧栏改了记忆 模型下一轮还是看不见 是不是工具和页面没走同一份 store  
> 对一下 planner-api 和 memory_manage 别各写各的

> 夜间扫描把今天的草稿也抽进去了 只要昨天 单条截短一点 全天事件也设个上限 不然 prompt 太长

## 7. 上下文组装和 Token

**意图：** 历史别无限往 prompt 里堆；工具循环里别反复贴画像；压缩别把 function call 切断。

> 对话历史别无限往 prompt 里塞  
> 失败重试那些细节下一轮别让模型看见 只保留用户说的 助理回的 工具结果

> 画像别每个工具步骤都贴一遍 一轮贴一次就够  
> 如果这一轮已经贴过同一份 就跳过  
> 挂在 agent 第一步 别跟工具循环搅在一起

> 上下文快满的时候要压缩 但别把一次工具调用和它的结果切开  
> 尾巴最近的对话尽量留着 前面的做摘要  
> 压缩记录进日志就行 不要污染当前看到的那层

> 抽取 扫描 开场提示这些小调用不要进主对话历史 否则越聊越脏  
> 各自设个超时和 token 上限 卡住就放弃 不要拖死主循环

> 工具返回太长下一轮直接爆了 结果截断一下并标明已经截过

> 纯聊天不要先逼人选项目文件夹 但工具执行还是落在工作区里  
> chat-home workspace is not registered 这种就是没挂上 先把这个工作区注册好

## 8. 工具调用、待办订阅、调度

**意图：** 工具名少而稳；待办和记忆分开；调度别重入。

> 别给每个动作都注册一个工具 模型记不住  
> todo 记忆 订阅 这种做成一个工具名加 operator 就行 比如 create / list / complete  
> 参数不对要回给模型让它改 不要把进程打崩  
> 对用户隐藏内部 id 按标题找 找不到用中文说清楚

> 人设里写清楚 记住 → 记忆 明天下午三点 → 待办 每天提醒 → 订阅 别在回复里口头答应然后不调用工具

> 待办和记忆别塞一张表 记忆是长期画像 待办是带时刻的任务  
> planner.json 写的时候先写临时文件再 rename 避免写一半断电

> 订阅到期要进收件箱 调度 20 秒 tick 一次就行  
> 刷新提示和夜间扫描不要叠着重入 加个进行中的标记

> 侧栏开场那几条提示先用待办和记忆拼出来 马上能点  
> llm 生成成功了再换 条数不够用兜底补齐  
> 指纹没变就别反复打模型

> 能力中心把内置能力和已装 skill 列出来 用户 A 装的不要出现在用户 B 那边

> 再加一种能力的话走 defineTool 注册就行 不必改网关  
> 要出现在能力中心再补一条目录 人设里补一句什么时候调用

## 9. LLM 兜底和稳定性

**意图：** 主对话可以重试；抽取失败不能写脏数据。

> 主循环超时 空回复 限流这些按提供方策略重试就行 重试过程不要写进对话表面

> 抽取经常带一段 ```json 或者先解释两句 帮我把围栏剥掉 取出第一个完整对象  
> 非法类型就落到 preference 空内容丢掉 解析失败返回空 上层走规则

> 夜间扫描失败就跳过今天 不要写脏数据 明天还能补  
> 开场提示失败也没关系 先把兜底四条亮出来

> completeText 要有超时 模型没配好或者空响应打日志就行 别把异常抛到 http 和调度器 否则整个 tick 停了

> 空内容的完成不要进历史 不然下一轮模型会学到空白

## 10. 接口、隐私和测试

**意图：** 页面和工具同一份数据；密钥不回传；隔离和检索要有测试。

> planner-api 继续 json 进出 错了就 { error }  
> 记忆走 sqlite 待办订阅还是 json 别合并  
> worker 上如果打到 /identity 要跳回网关 不然换用户会写错目录

> 密钥不要进 git 配置接口只返回配没配过 不要把明文传回浏览器  
> 记忆检索也在本地做 不要送到外部 embedding

> 用户名只允许小写英文和点下划线 拒绝 ../ 和中文 避免路径穿越  
> 旧的扁平 .harness 第一次启动先备份再迁到 users/名字 失败就回滚 迁完做一下完整性检查

> 隔离和检索这两块测试要能跑  
> 同用户并发只起一个 worker 不同用户数据流要分开 未登录页面跳走 api 401  
> 记忆搜索中英混合 非整句话也能命中持仓那种条目

> 抽取规则 扫描去噪 hint 的 json 解析这三块现在基本靠手工看 先补纯函数测试 先别上端到端 ui

> 重点：记忆系统设计（写入时机 存储结构 检索策略） 多轮对话上下文和 token 工具调用稳定性 llm 兜底重试降级 用户数据隔离 后台服务架构和接口 可扩展性 测试与代码质量
