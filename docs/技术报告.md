# 智能助理技术报告

个人 AI 助理：在浏览器中完成多轮对话、待办、订阅提醒、长期记忆与能力扩展。本文档按实现说明系统设计，覆盖记忆、上下文与 Token、工具调用、LLM 兜底、用户隔离、后台接口、可扩展性与测试。

仓库：https://github.com/LucasIdeal/personal-agent  
默认入口：http://127.0.0.1:3080

---

## 1. 项目概述

系统在 DeepSeek Harness（`dsh`）运行时上叠加 `personal-assistant` 插件与多用户身份网关。浏览器打开即可用，不必先选代码项目。对话、待办、订阅、记忆与模型密钥按用户写入 `.dsh/users/<英文名>/`，互不混用。

为方便内网体验，入口只要求企业微信英文名，不接 OAuth / 密码。身份校验可以替换为正式登录；**数据隔离已经按用户进程与目录落地**，不同用户的会话、记忆、待办彼此独立。

| 能力 | 实现要点 |
|---|---|
| 多轮对话 | 会话事件溯源 + 表层压缩 + 用户画像注入 |
| 长期记忆 | SQLite 存储；主动写入、夜间扫描、启发式 / LLM 抽取 |
| 检索 | 关键词分词 + 本地 n-gram 哈希向量，RRF 融合 |
| 待办 / 订阅 | JSON 状态机 + 20s 调度 tick，到期写入收件箱 |
| 工具 | `defineTool` 注册，`operator` 路由 CRUD |
| 多用户 | 网关按 Cookie 拉起独立 worker，`DSH_HOME` 隔离 |

## 2. 总体架构

```
浏览器
  │  Cookie: personal_agent_identity
  ▼
身份网关  :3080   scripts/user-gateway.mjs
  │  HTTP / WebSocket 反代
  │  每用户一个 Node 子进程
  ▼
用户 Worker
  DSH_HOME=.dsh/users/<英文名>
  ├── dsh Web + agent-loop
  ├── personal-assistant 插件
  │     工具 / HTTP / 调度 / 记忆上下文
  └── 用户数据
        sessions.sqlite
        planner/memory.sqlite
        planner/planner.json
        chat/notes/
        settings.yaml · .credentials.yaml
```

启动路径：`start.mjs` 检查 Node、依赖与前端构建，默认走多用户网关；`--single-user` 绕过网关，兼容旧的单目录模式。网关为每个英文名分配回环端口，健康检查通过后再反代。空闲 30 分钟且无 WebSocket 时回收 worker。

插件通过 Cordis YAML 补丁挂载（`app/extensions/personal-assistant/cordis.yml`）：替换系统人设、将会话持久化切到 SQLite、注册内置「对话」工作区，并加载助理插件。

## 3. 记忆系统设计

### 3.1 写入时机

记忆不在每轮对话无条件落库，而是三条受控路径：

| 来源 `source` | 时机 | 行为 |
|---|---|---|
| `active` | 用户明确说「记住 / 记下 / 记一下」；或侧栏确认记忆卡片 | 启发式先抽；抽不出再调 LLM。带明确时刻的条款进待办，不进记忆 |
| `scan` | 调度器在本地 0 点或启动补扫「昨天」会话 | 只从用户原话抽稳定偏好 / 事实；过滤助理草稿与 Markdown 碎片 |
| `manual` | 侧栏直接新增 | 用户手写，不经抽取 |

抽取策略（`memory-llm.ts` + `memory-extract.ts`）：

1. 规则意图：`记住` 类触发写入；`你记着什么` 走检索，不写。
2. 启发式：按分句切分，时间线索进待办，口味 / 习惯进 `preference`，身份信息进 `fact`。
3. 启发式为空才调用 LLM，要求只输出 JSON；解析失败或超时则退回启发式结果（通常是空）。
4. 扫描路径另有噪声过滤器，丢掉「老师您好」、列表符号、半句等扫描赝品。
5. 内容指纹去重：规范化后相同的句子更新已有条目，不插重复行。

扫描每天最多成功记一次（`memory_scans.day` 主键）。会话摘录只读 `sessions.sqlite`，跳过插件注入的「用户画像」消息与待办会话前缀，单条文本截到 500 字，全天最多 400 条事件，prompt 再截到 12 000 字符。

### 3.2 存储结构

`MemoryStore` 使用 Node 内置 SQLite（WAL、`STRICT` 表）：

```sql
memories (
  id TEXT PRIMARY KEY,          -- mem_<8位 uuid>
  kind TEXT NOT NULL,           -- preference | fact | note
  content TEXT NOT NULL,
  category TEXT NOT NULL,       -- 饮食 / 工作 / 沟通 / 生活 / 股票 …
  source TEXT NOT NULL,         -- active | scan | manual
  status TEXT NOT NULL,         -- active | archived
  created_at TEXT, updated_at TEXT
)
memory_scans (day PRIMARY KEY, scanned_at, proposed, written)
hint_sets (id='current', fingerprint, payload, generated_at)
```

索引：`memories_status_updated (status, updated_at DESC)`。列表查询上限 400 条，避免把整库塞进检索池。

待办与订阅不进 SQLite，而在 `planner.json` 中原子写（先写临时文件再 rename），与记忆职责分开：记忆是长期画像，待办是带时刻的任务。

### 3.3 检索策略

混合检索，**任一通道命中即可**，不是 AND：

1. **关键词**：NFKC 小写；拉丁词与 CJK 按脚本切开；中文做 2/3-gram；过滤停用词。打分 = 命中 token 数 / token 总数。
2. **本地向量**：`ngram-hash-v1`，384 维 hashing trick（FNV-1a 变体 + 随机符号），L2 归一化后余弦相似度，阈值 0.16。
3. **融合**：Reciprocal Rank Fusion，`k = 60`。默认返回 24 条。

该方案不依赖云端 embedding，密钥与记忆都留在本机。`info_search` 在记忆之外还会用同一套分词扫待办、订阅和笔记。

对话侧还有一条「常驻画像」通道：每轮第一步把最多 40 条 active 记忆格式化为「用户画像」插件消息注入（见下一节）。点查走 `memory_manage search` / `info_search`，避免每轮把全库塞进 prompt。

## 4. 多轮对话上下文管理与 Token 控制

上下文分三层，避免「把历史原样无限拼进 prompt」。

### 4.1 会话真源与表层

会话是仅追加的事件日志（`sessions.sqlite`）。模型看到的是 **surface**：`user/message`、`assistant/message`、`tool/result` 的有序投影。压缩、重试、钩子等事件只进日志，不进表层，因此失败分片和退避细节不会污染下一轮请求。

内置 `chat` 工作区让 Web 编辑器不必先选代码目录；工具仍在该目录内执行。

### 4.2 用户画像注入

`registerMemoryContext` 挂在 `agent/pre-step`（`prepend: true`）：

- 仅在 `step === 1` 且 `turn >= 1` 时注入，避免工具循环每一步重复贴画像。
- 若最新一条插件 snapshot 已是同一份 brief，则跳过。
- 无记忆时不注入，节省 token。

画像与工具 schema、系统人设一起进入组装后的请求。人设要求遵守画像，并用 `memory_manage` / `todo_manage` 等工具，而不是在回复里编造偏好。

### 4.3 Token 计量与压缩

运行时使用 `ctx.tokenMeter` 按当前路由的上下文窗口计量系统提示、工具 schema、历史与工具结果。`dsh-compaction-basic` 在步骤边界做压力检查：

| 策略 | 默认 |
|---|---|
| 压缩阈值 | 路由窗口的 80% |
| 逐字保留尾部 | 窗口的 16% |
| 摘要 maxTokens | 8192 |
| 压力重试 | 1 次额外尝试 |
| 溢出恢复 | 提供方确认 context overflow 后再剪枝 / 摘要 |

压缩只切在工具调用与结果配对平衡的位置，避免留下未闭合的 function call。超大工具结果可先剪枝；若压力已回落则不再摘要。检查点以带 `<compacted-summary>` 的替换 user 消息进入表层，原事件仍在日志里可查。

助理侧的辅助 LLM 调用另有硬上限：抽取 600 tokens / 12s，扫描 1500 tokens / 15s，提示生成 800 tokens / 20s；扫描 transcript 截断到 12 000 字符。这些调用走 `ctx.llm.stream()`，不进入 agent-loop 历史。

工具结果渲染也有上限（例如 workflow `maxResultChars`），过长内容截断并标注，避免单次工具输出撑爆下一轮。

## 5. 工具调用：注册、路由与稳定性

### 5.1 注册

统一走 `ctx.tools.register(defineTool({...}))`。参数 schema 在注册时校验；模型乱传 enum、缺必填字段会变成 `INVALID_ARGS`，进入正常错误结果路径，而不是进程异常。输出必须声明 `output.schema` + `render`，保证日志回放和 UI 卡片一致。

当前助理注册的工具：

| 工具 | 职责 |
|---|---|
| `todo_manage` | 待办 CRUD（create / list / complete / update / delete） |
| `subscription_manage` | 订阅 CRUD + pause / resume |
| `memory_manage` | 记忆 CRUD + 混合检索 |
| `info_search` | 跨记忆 / 待办 / 订阅 / 笔记检索 |
| `task_brief` | 过期 / 今日 / 后续 / 运行中订阅摘要 |
| `list_capabilities` | 内置能力 + 已安装 Skill |
| `save_note` / `list_notes` / `read_note` | 笔记文件 |

`cordis.yml` 中的人设把自然语言意图映射到上述工具（「记住」→ 记忆，「明天下午三点」→ 待办，「每天提醒」→ 订阅）。

### 5.2 路由

采用 **单工具 + `operator` 枚举**，而不是为每个动词注册一个名字：

- 模型只需记住少量工具名，schema 更稳。
- `switch (operator)` 集中校验必填字段，未知 operator 显式抛错。
- 对用户隐藏内部 id，按 title / content 查找；查找失败返回可读中文错误，供模型下一轮修正。

执行流水线（运行时）：

```
tools/pre-execute（允许 / 拒绝 / 询问）
  → 单调 guard
  → tools/execute（超时、信号、指标）
  → tools/post-execute
  → finalizeContent
  → tools/result（仅观测）
```

并行安全的调用受 `maxParallelToolCalls`（默认 10）滚动池限制。取消是协作式 `AbortSignal`：分发前取消为 `ABORTED_BEFORE_DISPATCH`，执行中取消将成功结果替换为 `ABORTED`。

### 5.3 稳定性

- **参数**：`defineTool` 在进入 `execute` 前校验类型与 enum。
- **幂等写入**：记忆按内容指纹去重；扫描跳过已存在条目。
- **路径安全**：笔记 slug 只保留 `[a-z0-9-]`；静态资源 `resolve` 后必须落在 `webDir` 内，否则 403。
- **调度隔离**：hint 刷新与记忆扫描用 in-flight 标志，避免 20s tick 叠加重入。
- **Skill 安装**：CLI 失败则回退到 COS zip；slug 去掉危险字符；安装目录限制在用户 skills 根下。

## 6. LLM 输出不稳定时的兜底、重试与降级

LLM 失败被分成两条链路：**对话主循环**与**助理辅助任务**（抽取、扫描、提示）。

### 6.1 对话主循环

`dsh-llm-retry` 在 `agent/request-error` 上按提供方 `retryPolicy` 重试。默认 normal 模式对 `EMPTY_RESPONSE`、`RATE_LIMIT`、`SERVER`、`TIMEOUT`、`TRANSPORT` 重试两次，500 ms–10 s 指数退避 + 10% jitter。重试事件不进入表层，模型看不到失败分片。上下文溢出由 compaction 独立恢复，预算不与提供方重试混计。

模型调用需要 `provider` + `model`；`maxTokens` 作为单次输出上限写入请求头。空内容完成不会进入派生消息历史。

### 6.2 辅助任务：解析兜底

辅助调用要求「只输出 JSON」。实际输出常带 markdown 围栏或前言，因此：

1. 剥 ```` ```json ```` 围栏，按括号深度截取第一个完整对象。
2. 字段白名单：非法 `kind` 回落为 `preference`；空 content / title 丢弃。
3. 解析失败返回 `null`，上层改用启发式或已有缓存。

`completeText` 同时使用 `AbortSignal.timeout` 与 `Promise.race`；LLM 未注入、路由解析失败、空响应一律返回 `null` 并打日志，不抛到 HTTP / 调度器。

### 6.3 降级策略

| 任务 | 主路径 | 降级 |
|---|---|---|
| 主动记忆抽取 | 启发式；不足再 LLM | 启发式结果（可为空） |
| 夜间扫描 | LLM + 噪声过滤 | 跳过本日，不写脏数据；次日可补 |
| 开场提示 | 先用待办 / 记忆拼 4 条 fallback，立刻可点 | LLM 成功后再覆盖；条数不足用 fallback 补齐 |
| 模型路由 | 优先 chat 类，避开 reasoner / r1 | 该提供方第一个模型，再退 `deepseek-chat` |
| Skill 安装 | `skillhub` CLI | COS zip |
| 身份 Worker | 健康检查成功才反代 | 启动失败 503；上游断开 502 |

提示生成是「先可用、后更好」：指纹未变则直接返回缓存；强制刷新时先换一套 fallback，再异步打 LLM，避免侧栏空白。

## 7. 用户数据隔离与隐私保护

### 7.1 隔离模型

身份网关读 HttpOnly Cookie `personal_agent_identity`，规范化为小写英文名后：

1. `initializeUserRoot` 创建 `.dsh/users/<name>/` 与 `chat/`。
2. 子进程环境变量 `DSH_HOME` 指向该目录。
3. 会话库、记忆库、待办 JSON、笔记、密钥、已装 Skill 全部落在该树下。

因此隔离是 **进程 + 目录**，不是应用内 `WHERE user_id = ?`。测试覆盖：同一身份并发请求只起一个 worker；不同身份走不同端口与 HTTP 流；未登录页面 303、API 401、WebSocket 拒绝。

用户名约束：`^[a-z][a-z0-9._-]{0,63}$`，拒绝 `../`、中文、数字开头，避免路径穿越。

### 7.2 登录强度（体验取舍）

当前实现：

- 输入企业微信英文名即可发 Cookie，无密码、无 OAuth。
- Cookie：`HttpOnly; SameSite=Lax`，HTTPS 下补 `Secure`。
- 英文名校验防止非法目录名，**不等于认证**。

这是为内网演示降低摩擦。换成企业微信 OAuth / OIDC 时，网关只需在 `/identity/select` 之后写入同一 Cookie（或改为服务端 session），worker 与 `DSH_HOME` 布局不用改。API 未带身份已返回 401，扩展鉴权的挂钩已经存在。

### 7.3 隐私

- `.dsh/`、`.credentials.yaml`、`.env` 在 `.gitignore` 中，密钥不进 Git。
- 密钥经 `credentials` 服务按引用存储，配置 API 只回传「是否已配置」，不回传明文。
- 记忆检索与 embedding 均在本地完成。
- 静态文件 handler 禁止目录穿越。
- 旧版扁平 `.dsh/` 首次启动会备份后迁到指定用户，迁移失败则从备份回滚；SQLite 迁移前后做 `integrity_check`。

## 8. 后台服务架构与接口设计

### 8.1 进程角色

| 进程 | 职责 |
|---|---|
| 网关 | 身份页、Cookie、按用户启停 worker、HTTP/WS 反代、Gzip、静态缓存 |
| 用户 Worker | agent-loop、LLM、工具、会话、插件 HTTP |
| 调度 tick（worker 内） | 到期订阅、提示刷新、昨日记忆扫描 |

网关对 `/planner-api` 做健康检查（2xx 且 `content-type` 含 json）。Worker 上的 `/identity*` 303 回网关 3080，避免用户在子端口上「换身份」却写错目录。

### 8.2 Planner HTTP

前缀 `/planner-api`，JSON in / JSON out。错误统一 `{ error }`，业务 400，未知路径 404。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/planner-api` | 待办、订阅、未读收件箱、记忆、提示、能力一览 |
| GET/POST | `/planner-api/setup` | 读 / 写模型提供方、密钥引用、默认模型 |
| GET | `/planner-api/memories?q=` | 列表或混合检索 |
| POST | `/planner-api/memories` | 手动新增 |
| PATCH | `/planner-api/memories/:id` | 改 kind / content / 归档 |
| DELETE | `/planner-api/memories/:id` | 删除 |
| POST | `/planner-api/memory/extract` | 从一段文本抽取（确认卡片前） |
| POST | `/planner-api/memory/commit` | 确认写入记忆 + 待办 |
| POST | `/planner-api/memory/scan` | 强制扫描昨天 |
| POST | `/planner-api/todos` 等 | 待办 / 订阅 CRUD |
| GET | `/planner-api/hints` | 开场提示；无缓存则后台刷新 |
| GET/POST | `/planner-api/skills*` | 已装列表、SkillHub 搜索 / 安装 / 刷新 |
| GET | `/planner-api/capabilities` | 能力中心目录 |

前端静态资源挂在 `/planner-ui`，由 `webServer.tapIndex` 注入 CSS/JS。UI 与工具读写同一份 `MemoryStore` / `PlannerStore`，避免「侧栏改了、模型看不到」。

### 8.3 模型配置接口

`/planner-api/setup` 支持 DeepSeek、OpenAI、Anthropic，以及任意 OpenAI 兼容网关（通义、智谱、Moonshot、SiliconFlow、Ollama 等）。自定义提供方 ID 限制为 kebab-case。密钥写入 credentials，settings 只存 `apiKeyEnv` 引用。未配置时前端弹窗；已有默认模型则不再打扰。

## 9. 系统可扩展性

### 9.1 新增工具

1. 在 `tools.ts` 或新模块中 `defineTool`。
2. 于 `index.ts` 的 `apply` 里 `ctx.tools.register`。
3. 如需出现在能力中心，向 `CAPABILITY_PLUGINS` 追加一项（`action`: `prompt` / `open-planner` / `invoke-skill`）。
4. 复杂流程可再加一条 `skills/<name>/SKILL.md`，启动时同步到用户 skills 目录。

工具名进入系统提示的 schema 列表；人设里补一句「何时调用」即可被模型发现。不必改网关或存储布局。

### 9.2 新增记忆类型

`MemoryKind` 目前是 `preference | fact | note`。扩展步骤：

1. 在 `types.ts` 联合类型中增加取值。
2. 抽取 prompt（`EXTRACT_SYSTEM` / `SCAN_SYSTEM`）与启发式规则同步新 kind。
3. `formatBrief` / 侧栏文案增加中文标签。
4. 检索无需改：仍按 content + category 建 haystack。

存储是开放 TEXT 列，旧库不必迁移 schema。若将来要按 kind 做不同过期策略，只需加过滤器，不必换引擎。

### 9.3 新增能力 / Skill

能力中心 = 内置插件列表 ∪ 扫描到的 `SKILL.md`。Skill 可来自：

- 插件自带（memory / planner / capabilities / skillhub）；
- SkillHub CLI 或 COS zip 安装到该用户的 `skills/`。

`CapabilityCatalog.refresh` 合并后按 `order` 排序。安装成功会刷新目录并重算提示。用户 A 安装的 skill 不会出现在用户 B 的 worker 里。

### 9.4 新增模型提供方

走 setup 的 `custom` 预设即可，无需发版。若要一等公民预设，在 `LLM_PRESETS` 增加一项并接到 settings namespace。

## 10. 测试与代码质量

### 10.1 本仓库聚焦用例

```
npm run test:user-isolation
# node --test scripts/user-data.test.mjs tests/user-gateway.test.mjs
```

| 文件 | 覆盖 |
|---|---|
| `scripts/user-data.test.mjs` | 用户名规范化；拒绝路径穿越；用户根目录幂等创建；扁平数据备份迁移与失败回滚 |
| `tests/user-gateway.test.mjs` | 身份页与 Cookie；未登录 401/303/WS 拒绝；同用户单例 worker；异用户流隔离；崩溃重启；WS 转发；空闲回收 |
| `app/extensions/personal-assistant/tests/memory-search.spec.ts` | 中英混合分词；非整句子串仍能命中持仓记忆；embedding 通道独立命中；余弦区分相关 / 无关 |

运行时（`app/packages`）另有 agent-loop、tools、llm-retry、compaction、session 等包级测试，约束 Function Calling 流水线、重试不污染历史、压缩边界等。

### 10.2 质量约束

- TypeScript 严格模块、显式 schema（`defineTool` / Cordis `Schema`）。
- SQLite `STRICT` + WAL；迁移前后 `quick_check` / `integrity_check`。
- 状态文件原子写（临时文件 + rename）。
- 网关与插件对畸形 JSON、超大表单（8 KB）、未知路由有明确状态码。
- 密钥与会话目录永不入库。

当前缺口：抽取启发式、扫描噪声过滤、hint JSON 解析以手工与演示验证为主，自动化仍集中在检索与隔离。补测时优先这三块纯函数。

## 11. 小结

系统把「个人助理」拆成可独立演进的几层：网关负责身份与进程隔离，worker 负责对话循环，插件负责记忆 / 待办 / 能力，运行时负责工具协议、Token 压缩与提供方重试。

记忆只在明确意图、用户确认或夜间扫描时写入；检索用本地关键词 + 哈希向量，不把隐私送到外部 embedding。多轮上下文靠表层投影、画像按轮注入和窗口压力压缩控制 token。工具以少量注册名 + operator 路由，校验失败可回给模型修正。LLM 不稳定时，对话走提供方重试，助理任务走超时、JSON 修复和规则 / 缓存降级。

登录刻意保持轻量，但用户数据已按目录与进程隔离；加强认证只需替换网关的身份来源，不必改记忆与对话实现。扩展新工具或记忆 kind 走注册表与类型联合，不必改存储引擎。
